# ecmd 2.0

2.0 is the breaking release that makes the derive the whole surface: one field attribute, every
key typed, every parsing policy on the field it governs, and a scanner that matches the reference
commands where 1.0 deviates. This document is the implementation plan. One pull request carries
the work as an ordered commit stack, and its merge releases 2.0.0 through the existing release
job with no manual step.

Three reviews on 2026-09-02 produced the plan: a POSIX and GNU conformance audit of the scanner,
a duplication review of the derive keys and the Rust API, and a survey of every ecmd use in
shelios (the esh shell, the only consumer). The survey settled one thing first: shelios pins ecmd
at git rev `16deaf6`, a commit from before the 1.0 API, so nothing compiles against 1.0 today and
shelios migrates from that rev straight to 2.0. 1.0's names constrain nothing.

## The derive

```rust
/// Concatenate files and print on the standard output
///
/// With no FILE, or when FILE is -, read standard input.
///
/// # Exit Status
/// 0 on success, 1 on any error
#[derive(Command)]
#[command(style = gnu, dialect = clap)]
struct Cat {
    /// equivalent to -vET
    #[arg(short = 'A', long)]
    show_all: bool,
    /// number nonempty output lines, overrides -n
    #[arg(short = 'b', long, clears(number))]
    number_nonblank: bool,
    /// number all output lines
    #[arg(short, long, clears(number_nonblank))]
    number: bool,
    /// use N spaces for a tab
    #[arg(short, long, value_name = "N", optional_value, missing = "8")]
    tabs: Option<u32>,
    files: Operands,
}
```

The derive infers everything the struct already says. The command name is the struct ident in
kebab case, the summary is the first doc paragraph, the description the paragraphs after it, the
after-help the `# Options` block, the exit status the `# Exit Status` block, and a flag's help its
own doc comment. A bare `short` is the field's first letter and a bare `long` the kebab field name
with a leading underscore stripped. A field is a flag when its `#[arg]` carries `short` or `long`,
and otherwise its type decides: `String` is a required positional, `Option<String>` an optional
one, `Operands` the rest slot, and a positional needs no attribute at all. Enum-valued keys take a
bare ident (`style = gnu`), never a string.

The field type table from the README holds unchanged (`bool`, `Polarity`, `Option<T: FromStr>`,
`Vec<String>`, `Vec<PolarVal>`, `String`, `Option<String>`, `Operands`). A `Vec` flag always
repeats.

### `#[command(...)]`

| Key | Replaces | Meaning | Default |
|---|---|---|---|
| `name = "cd"` | `name`, which was required | the command name | the struct ident in kebab case |
| `usage = "cd [-LP] [dir]"` | `short_doc` | the usage line help prints | generated |
| `style = gnu` | `style = "gnu"` | the argument conventions, `posix` or `gnu` | `posix` |
| `dialect = clap` | `help_style = "clap"` | the help dialect: `bash`, `gnu`, `clap`, `clap_wide` or `util_linux` | `bash` under `posix`, `gnu` under `gnu` |
| `lenient` | `lenient` | an unknown flag becomes an operand | off |
| `no_permute` | `no_permute` | the first operand ends flag scanning | off |
| `no_repeat` | `no_override` | a repeated scalar flag is an error, in every style | off |
| `exact_long` | `tag(exact_long)` | a long option needs its full name | off |
| `help = long`, `help = none` | nothing | `--help` alone, or no reserved help spelling | `--help` and `-h` under `gnu` |
| `version = long`, `version = none` | `no_implicit_version` | `--version` alone, or no reserved version spelling | `--version` and `-V` under `gnu` |
| `noop = "eE"` | `noop` | short flags accepted and dropped | none |
| `authored = options`, `authored = page` | `tag(gnu_literal_tail)`, `tag(verbatim_help)` | the `# Options` block replaces the options block, or is the whole page | off |
| `help_desc = "..."`, `version_desc = "..."` | the same tags | the wording of the two reserved rows (clap, util-linux) | the dialect's wording |
| `help_first`, `version_first` | the same tags | the reserved rows move to the top (clap) | last |
| `help_before = "color"` | `tag(help_before)` | `--help` sits before that option (clap) | last |
| `spaced` | `tag(help_spaced)` | a blank line between rows (clap_wide, util-linux) | off |
| `width = 27`, `pair_width = 27` | `tag(help_width)`, `tag(help_pair_width)` | the description column, and the one for the reserved pair (util-linux) | natural |
| `option_row(2, "label", "desc")` | `tag(help_row = "2\tlabel\tdesc")` | a help-only option row, an empty label and description for a separator (util-linux) | none |
| `arg_row(0, "label", "desc")` | `tag(arg_row = ...)` | a help-only argument row (clap) | none |
| `trailer = "name"`, `trailer = none` | `tag(man_page)`, `tag(no_trailer)` | the name in the `(1)` trailer, or no trailer (util-linux) | the command name |
| `tag(key)`, `tag(key = "value")` | `tag` | a key and value pair for the caller | none |

ecmd reads no tag. The 14 policy keys and the 14 help keys that `tag(...)` carried in 1.0 are
typed keys now, so a misspelled key fails to compile where it used to parse as nothing.

Under `posix` the scanner reserves no spelling at all, and `help` and `version` change nothing.
Under `gnu` a declared `-h` or `-V` always wins over the reserved one, as in 1.0.

Keys that exist in 1.0 and not in 2.0: `equals_only` (getopt_long has no required-with-equals
mode; a flag whose long form needs `=` is an `optional_value` flag), `spread` (inferred from
`Operands`), `extra_help` (the `# Options` doc block), `long = ""` (a flag with no `long` key has
no long name), `help_values`, `help_label`, `short_doc`, `help_style`, `no_override`,
`no_implicit_version`, `repeatable`, `reject_hyphen_values`, and every ecmd-read `tag` key.

The derive refuses, at compile time: an unknown key; a flag key (`short`, `long`, `alias`,
`visible_alias`, `label`, `values`, `hide_values`, `no_hyphen_values`, `repeat`, `clears`,
`unimplemented`, `optional_value`, `missing`, `value_at`, `numeric`) on a positional; `required`
or `num_args` anywhere but the `Operands` field; `default` on a required positional; a positional
after `Operands`; a required positional after an optional one; a duplicate short or long; `clears`
naming a field that is not a flag or the flag itself; `missing` without `optional_value`;
`hide_values` without `values`; `numeric = first` on more than one flag; a short outside ASCII.

### Value policies

A valued flag with no policy takes its value attached (`-xVAL`, one leading `=` stripped for a
short, `--x=VAL`) or from the next argument (`-x VAL`, `--x VAL`). With `no_hyphen_values` the
next argument may not open with `-`, and the scanner reports `MissingValue` when a declared option
stands there and `UnknownFlag` when an undeclared one does.

| `optional_value` | Without an attached value |
|---|---|
| bare | reports `missing` and leaves the next argument alone (glibc's `::`) |
| `next` | takes the next argument unless it reads as an option, else `missing` |
| `any` | takes whatever argument follows, else `missing` |
| `numeric` | takes the next argument when it is a numbering spec, else `missing`; the long form always takes the next argument |
| `exact` | reports `missing` when the short stands alone in its cluster, else takes the next argument unless it reads as an option |

A numbering spec is digits, `-` followed by digits, or one ASCII character followed by digits.
1.0 accepted any token that opened with `-` as a spec, so `nl -n -t` swallowed `-t`. An argument
reads as an option when it opens with `-` and is longer than one byte, or opens with `+` and names
a declared polar flag.

`value_at = attached` makes `-x VAL` a `MissingValue`, `value_at = separated` reads `-xVAL` as a
cluster and takes only the next argument, and `value_at = prefixed` reads `-5x` as `-x 5`.

`numeric = minus` reads `-N` and `-N:M` anywhere into the flag and `numeric = plus` reads `+N` and
`+N:M`, the first occurrence winning (`tail +3`, `pr -3`). `numeric = first` reads a leading `-N`
into the flag (`head -5`) and reports `FirstNumericValue` when `-N` appears later. 1.0 turned `-0`
and a count past `usize` into operands; 2.0 routes every leading `-N` to the flag, so `head -0` is
`-n 0` and an overflowing count fails in the field's `FromStr` with `InvalidValue`, which is what
coreutils prints.

A command has one mode axis. Two flags with different `mode` values report `ConflictingFlags`
naming both, as `exclusive_flags` did, and an `Operands` slot with a `mode` conflicts with a flag
of another mode.

## The Rust surface

Every public item stays at the crate root. The naming rule is one word per concept in three
places: the attribute key, the builder setter, and the accessor. A setter is spelled like its key
and consumes the builder. An accessor is the plain noun (`long()`, `help()`, `default()`), or
`is_` for a state (`is_hidden()`), or a verb for a capability (`repeats()`, `takes_value()`). No
accessor takes a `get_` prefix, which is why `Flag` and `Positional` gain builders: a setter and an
accessor cannot share a name on one type.

| Item | 2.0 |
|---|---|
| `Command` | `def()`, `from_scan(&Scan)`, `parse(args)` with a default body of `from_scan(&def().scan(args)?)`, `parse_env()` |
| `Def` | accessors `name`, `about`, `description`, `after_help`, `exit_status`, `usage` (authored or generated), `help`, `style`, `dialect`, `lenient`, `permute`, `no_repeat`, `exact_long`, `help_reserved`, `version_reserved`, `flags`, `flag(id)`, `flag_named`, `positionals`, `rest`, `tags`, `tag`, `has_tag`, `scan`, `into_builder` |
| `DefBuilder` | `new`, `name`, `about`, `description`, `after_help`, `exit_status`, `usage`, `style`, `dialect`, `lenient`, `permute`, `no_repeat`, `exact_long`, `help`, `version`, `noop`, `flag`, `positional`, `rest`, `tag`, `without_tag`, `authored`, `help_desc`, `version_desc`, `help_first`, `version_first`, `help_before`, `spaced`, `width`, `pair_width`, `option_row`, `arg_row`, `trailer`, `build` |
| `Flag` | accessors `id`, `short`, `long`, `aliases`, `visible_aliases`, `answers_to`, `kind`, `takes_value`, `help`, `value_name`, `label`, `default`, `values`, `hides_values`, `is_hidden`, `is_unimplemented`, `repeats`, `allows_hyphen_values`, `optional_value`, `missing`, `value_at`, `numeric`, `mode` |

`DefBuilder::flag` and `positional` and `rest` take `impl Into<Flag>` and `impl Into<Positional>`,
and each builder converts, so a runtime definition reads as one chain:

```rust
let ls = Def::builder("ls")
    .about("List directory contents.")
    .style(Style::Gnu)
    .flag(Flag::builder().short('a').long("all").help("do not ignore entries starting with ."))
    .flag(Flag::builder().short('w').long("width").value_name("COLS").help("assume screen width"))
    .rest(Positional::builder("files"))
    .build();
```

`Def::into_builder` returns the builder over an existing definition, so a caller renames a
definition, changes its usage line, turns permutation off, or adds and removes tags without
touching a field. That replaces `with_name` and `with_tag` and covers everything shelios does to
a definition at runtime today.

The cut list: `Flag::new`, `long_only`, `value`, `desc`, `hidden`, `once`,
`reject_hyphen_values`, `possible_values`, `help_values`, `default_value`, `help_label`,
`long_name`, `long_names`, `flag_kind`, `description`, `is_implemented`, `is_repeatable`,
`accepted_values`, `listed_values`, `assign_id`; `Positional::new`, `desc`, `label`,
`default_value`, `hidden`, `spread`, `description`, `shown_as`, `is_spread`; `DefBuilder::flags`,
`positionals`, `tags`, `short_doc`, `help_style`, `extra`, `no_implicit_version`;
`Def::short_doc`, `help_style`, `extra`, `with_name`, `with_tag`, `policy`; `HelpStyle` and
`from_parse_style`; the public `SYNTHETIC_BASE`, `def::text` and the nine `pub fn` in `help/`.
`__private` keeps `RawDef`, `RawFlag`, `RawPositional` and `Tag`, and loses `Policy`,
`ValueMode`, `ValueRule`, `NumericRule` and `ExclusiveRule`, whose facts move onto `Flag`,
`Positional` and `Def`.

With the `rkyv` feature `Def` derives `Archive`, `Serialize` and `Deserialize` as in 1.0. A struct
that holds a `Def` archives it as a plain field, so the `with` adapter and the hand-written bounds
shelios carries for its 0.x definition type go away.

## The scanner

Each change below comes from the conformance audit, and each lands as its own commit with a test
that compares against the reference command.

1. A lenient operand ends option scanning under `posix`. 1.0 pushed `-xyz` as an operand and then
   parsed `-n` as a flag; bash's `echo -xyz -n` prints both.
2. An operand produced on the numeric path obeys `no_permute` and the `posix` order rule. 1.0
   skipped the order check for it.
3. A numbering spec needs digits after `-`, so `-n -t` no longer consumes `-t`.
4. A leading `-0` and an overflowing count route to the `numeric = first` flag like any count.
5. The repeat rule applies in every style. 1.0 checked it under `gnu` alone, so `no_override` and
   `repeatable` and `Flag::once` were inert on every `posix` command.
6. `AmbiguousOption` carries the candidates, and its `Display` prints
   `--co: option is ambiguous; possibilities: '--color' '--context'`.
7. The value-boundary test (`is_declared_option`) asks the definition which shorts are reserved,
   where 1.0 hard-coded `h` and `V`, so `version = long` and `posix` commands stop treating an
   undeclared `-V` as an option.
8. `docs/parsing.md` stops describing `-o --all` as `MissingValue` by default; hyphen values are
   allowed by default and `no_hyphen_values` turns that rule on.

Two 1.0 behaviours stay on purpose: a short strips one leading `=` from an attached value
(`-o=file` is `file`, where getopt gives `=file`), and `-h` and `-V` are reserved under `gnu`.
esh's coreutils pin `-h` as help and `-V` as version (the timeout, b2sum and hostid tests), and
procps and util-linux tools own real `-V` and `-h`, so the default stays and `help = long` or
`version = long` gives a command the coreutils error for `cat -h`.

## The release

PR #12 merges first and nothing else lands on `main` before it. The release script on `main`
still runs cargo-semver-checks against a baseline clone, and that clone drops the README symlink,
so the baseline fails to build and the bump logic reads every merge as a major. PR #12 carries
the worktree-based `scripts/semver-check.sh`, which passes against v1.0.0. Trusted publishing on
crates.io must be configured before the 2.0 merge, since that run is the first one that publishes.

The 2.0 work is one pull request off `main` titled `feat!: ecmd 2.0`, labeled `semver-major` by
the author and `size-exempt` by the reviewer. The semver check fails against `main` and the label
accepts it. On merge, `release.yml` runs `scripts/release.sh`, which sees the `!` subjects since
v1.0.0, bumps to 2.0.0, writes the changelog, tags, publishes `ecmd-derive` and `ecmd`, and creates
the GitHub release.

## The commit stack

Each commit compiles and passes `just check` and `just test` on its own. The stack runs bottom
to top.

1. `fix(parse): end posix scanning at a lenient operand`
2. `fix(parse): order numeric operands like the rest`
3. `fix(parse): require digits in a numbering spec`
4. `fix(parse)!: route every leading count to its flag`
5. `fix(parse)!: apply the repeat rule in every style`
6. `feat(error)!: name the candidates of an ambiguous option`
7. `refactor(def)!: reserve help and version per definition` (`Reserved` on `Def`, replaces
   `no_implicit_version`, and the boundary test reads it)
8. `refactor(def)!: one value policy per flag` (`OptionalValue`, `ValueAt`, `Numeric` and `mode`
   on `Flag`, `num_args` and `mode` on `Positional`, `Policy` deleted, `equals_only` gone)
9. `refactor(help)!: typed layout on the definition` (a private `Layout` struct, `Authored`, the
   renderers stop reading tags, every help fixture stays byte-identical)
10. `refactor(def)!: builders for flags and positionals` (`FlagBuilder`, `PositionalBuilder`, the
    accessor names, the cut list, `values` enforcing and listing with `hide_values`, `Dialect`,
    `usage` returning the authored line, `into_builder`, `without_tag`, `has_tag`)
11. `feat(command)!: build a command from a scan` (`from_scan`, `parse` as a default method)
12. `feat(derive): accept #[arg] and the 2.0 keys beside the 1.0 ones`
13. `test(derive): move the corpus to the 2.0 keys`
14. `refactor(derive)!: drop the 1.0 keys and infer the names` (inference, typed command keys,
    `tag` for consumers only, the compile-fail cases above)
15. `docs: describe the 2.0 surface` (README with its doctests, `api.md`, `derive.md`,
    `parsing.md`, a `migrating.md` with the codemod table, `todo.md` trimmed)
16. `docs: add the ecmd skill` (`skills/ecmd/SKILL.md` at the repository root, written with the
    rust-skill-creator skill, covering the derive, the builder, the scan and every key)

Commits 1 to 11 change `crates/lib` and its tests. Commits 12 to 14 change `crates/derive`, its
`tests/ui` cases and `crates/lib/tests/derive.rs`, in the expand, migrate, contract order so the
corpus never breaks between commits. The derive's compile-fail messages change in 14, so the
`.stderr` files change there.

## Decisions

| Decision | Reason |
|---|---|
| derive plus helper attributes, no attribute macro | the helper attributes are part of the derive, one mechanism, and `#[command]` is optional |
| `long` is always written, no gnu implication, no `no_long` | the codemod cost is the same either way, it removes one style-coupled rule and the `long = ""` magic value |
| `values` enforces | a listed set the parser ignores misleads the user, and shelios validates those lists by hand today |
| `default` keeps both meanings on `Operands` | the one operand an empty slot holds is the value the slot takes when absent, one concept |
| `equals_only` cut | getopt_long accepts `--opt VAL` for every required argument |
| `mode`, not clap's `group` | ecmd's semantics are the inverse of clap's (flags sharing a value combine, flags with different values conflict), so reusing `group` would trap a clap user |
| `-h` and `-V` stay reserved under `gnu`, `help` and `version` opt out | esh pins them for its coreutils, and one key gives the coreutils error where a command wants it |
| no `prelude`, no owned `Scan`, no `UnknownCommand`, no rkyv adapter | one sed covers the prelude, shelios only borrows scans, the error arm is dead, and `Def` archives directly |
| no `POSIXLY_CORRECT` or `-W` key | esh owns the environment and calls `no_permute`, and no reference tool in the corpus takes `-W` |
| policies per field only | a command-level list resolved field names by ident or long spelling, and shelios feeds it both |
| builders over `get_` accessors | the coding guidelines ban the prefix, and `Def` already has one |
